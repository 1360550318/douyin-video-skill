# 常见问题

## 安装与环境

### Q：提示「浏览器未找到」或 `ffmpeg 未找到`
A：两者都可以用环境变量指定：

```bash
export DOUYIN_BROWSER="/path/to/chrome"
export DOUYIN_FFMPEG="/path/to/ffmpeg"
export DOUYIN_FFPROBE="/path/to/ffprobe"
```

Windows 上 `ffmpeg` 不带 `.exe` 后缀也能写。

### Q：`douyin_crawler.py` 报 playwright 找不到浏览器
A：执行一次 `playwright install chromium`。如果不想下内核，设
`DOUYIN_BROWSER_CHANNEL=msedge` 直接用系统 Edge。

### Q：提示「未找到浏览器（需要 Edge 或 Chrome）」
A：脚本启动前的依赖预检就会报出来。装 Edge 或 Chrome，或用 `DOUYIN_BROWSER`
指定可执行文件路径（Windows 常见位置已在 `scripts/config.py` 的候选列表里）。

### Q：`CDP 未就绪（Edge 启动失败）` 或端口冲突
A：换个调试端口：`--port 9334`（默认 9224；`douyin_channel.py` 固定用 9228）。
另外注意**不要让两个入口脚本同时跑**：它们用各自的 profile 子目录，但端口仍可能撞车。

### Q：依赖缺失的预检报错
A：脚本启动时会先跑 `config.check_deps()`，缺什么列什么、对应该装什么。
也可以自己查：

```bash
python -c "import sys; sys.path.insert(0,'scripts'); import config; print(config.check_deps())"
```

`douyin_crawler.py` 另需 `config.check_playwright()`，缺 playwright 时会提示
`pip install playwright && playwright install chromium`。

### Q：批量跑时特别慢
A：两个已知耗时点：
- **候选校验阶段**最慢（每条要开一次视频页等签名取流，约 5–8 秒），可用 `--limit` 控制条数
- OCR 不是瓶颈——批量模式走**进程内**调用，模型只加载一次

### Q：产物想放到别处
A：设 `DOUYIN_OUT` 环境变量，或在命令行用 `--out`（crawler 支持）。

## 单条视频

### Q：一直卡在等页面，最后超时
A：多半是页面没加载出真实 CDN 流（见 `技术原理.md` 坑 1）。先试 `--text-only` 看页面文字能不能拿到，
能拿到说明页面正常，只是取流慢——把 `--wait` 调大到 90。

### Q：下载下来的 MP4 没声音
A：**这是抖音 CDN 的结构，不是 bug**。画面流和声音流是两个独立地址，
`douyin_auto.py` 只挑到画面流。要音频用 `douyin_audio.py`。

### Q：提示 `403 / Fresh cookies needed`
A：这是 `douyin_analyze.py --url` 的 yt-dlp 兜底路径。抖音要浏览器活跃会话。
两个选择：

1. 设 `DOUYIN_BROWSER_COOKIES=chrome`（**会让 yt-dlp 读取你本机浏览器的 cookie，请自行判断风险**）
2. 用主链路 `douyin_auto.py`，它不需要任何 cookie

### Q：OCR 文字全是乱码 / 错字很多
A：OCR 识别的是画面里的字幕和贴字，小字号、艺术字、低对比度都会错。
这是「真实提取」的边界，脚本不会去猜。请人工复核关键信息。

### Q：`transcript.srt` 能直接用吗
A：可以，它就是标准 SRT。但时间轴是**按抽帧间隔估算**的（默认 3 秒一帧），
要精确到字需要调小 `--interval`（比如 1），代价是抽帧数和 OCR 时间上升。

## 博主作品采集

### Q：为什么只抓到 38 条，不是博主说的 133 条？
A：见 `技术原理.md` 坑 5。服务端对未登录会话只暴露最近 38 条，
`count` 参数调到 500 也一样。平台 `aweme_count` 还包含非视频作品和风控折叠项。
**脚本会把实收条数和平台声明数一起写进 `coverage.json`，不虚报。**

### Q：怎么才能补齐历史作品？
A：唯一干净路径是**每日增量账本**：每天跑一次采集，按作品 id 去重入账，长期累积。
本项目不提供「一次扒全」的开关，因为平台条件下做不到。

### Q：`coverage.json` 里 `declared_total` 和 `collected` 差很多，正常吗？
A：正常。`declared_total` 是平台声明的 `aweme_count`，包含了非视频作品和风控折叠项。

### Q：抓取很慢
A：≈5 秒/条是正常速度（每条都要开一次视频页等签名取流）。
可以调小 `--count` 减少单页请求量，但**总数不会因此变多**（见上一条）。

## 隐私与合规

### Q：它会读我的浏览器登录态吗？
A：主链路（`douyin_auto.py` / `douyin_channel.py` / `douyin_crawler.py`）**不会**。
它们用一个独立的 headless 浏览器 profile（默认 `~/.cache/douyin_video_skill`），
不碰你日常浏览器的任何数据。

唯一例外是 `douyin_analyze.py --url` 的 yt-dlp 兜底，需要显式设
`DOUYIN_BROWSER_COOKIES` 才会读 cookie，**默认关闭**。

### Q：会存别人的内容吗
A：产物（视频、OCR 文字、页面文字）存在 `DOUYIN_OUT` 目录里。
内容版权属于原作者，请勿商用或再分发。`.gitignore` 已经默认忽略所有产物文件，
避免误提交。

## 报 bug 前先看

跑一下这个确认基础环境：

```bash
python scripts/douyin_auto.py --help
python -c "import sys; sys.path.insert(0,'scripts'); import config; print(config.check_deps())"
```

`check_deps()` 返回空列表说明依赖齐全。
