# 技术原理

## 一、整体链路

```
抖音分享链接 (v.douyin.com/xxx)
        │
        ▼
  ┌──────────────────────────┐
  │ 1. 启动独立 headless Edge │  ← 独立 profile，不碰用户日常浏览数据
  │    + CDP 连接 (WebSocket) │
  └──────────────────────────┘
        │
        ▼
  ┌──────────────────────────┐
  │ 2. 页面自己完成签名取流     │  ← 关键：签名由抖音的 JS 完成，我们不碰
  │    等 <video>.currentSrc   │
  │    变成真实 CDN 地址       │
  └──────────────────────────┘
        │
        ├──────────────► 页面正文 innerText（平台自带章节要点/描述/作者/时间）
        │
        ▼
  ┌──────────────────────────┐
  │ 3. 从响应表挑真实 URL      │  ← performance 资源表 / Network.responseReceived
  │    （blob: 不能直接下载）   │
  └──────────────────────────┘
        │
        ▼
  ┌──────────────────────────┐
  │ 4. HTTP 下载 MP4           │
  └──────────────────────────┘
        │
        ▼
  ┌──────────────────────────┐
  │ 5. ffmpeg 抽帧 → RapidOCR  │  ← 本地 OCR，不联网、不调 API
  │    → 时间轴文字稿 + SRT     │
  └──────────────────────────┘
```

## 二、为什么必须用浏览器

抖音 2026-08 起关闭了纯 HTTP 通道：

| 尝试 | 结果 |
|---|---|
| `yt-dlp` 裸跑 | `403 / Fresh cookies needed` |
| 匿名 HTTP 请求视频页 | 只返回空壳，正文与播放流都没有 |
| 纯 Python 复刻签名 | 8 次里 3 次成功，其余 403，且 `a_bogus` 含随机字节，**本地逐字节复现 ≠ 服务端认可** |

`/aweme/v1/web/aweme/detail/` 是签名保护接口。社区项目
[Evil0ctal/Douyin_TikTok_Download_API](https://github.com/Evil0ctal/Douyin_TikTok_Download_API)
的 `signing/protection.py` 里有公开记录：纯 Python 签名 3/8 成功，其余 403，必须浏览器环境兜底。

**结论**：不要手搓签名逆向。让页面自己的 JS 去签名，我们只做观察者。

## 三、CDP 客户端

`douyin_auto.py` 里的 `CDP` 类是一个**最小实现**（约 100 行，无第三方依赖，只用 `websocket-client`）：

- 启动 `msedge --headless=new --remote-debugging-port=<port> --user-data-dir=<独立 profile>`
- 从 `http://127.0.0.1:<port>/json` 找到页面 target 的 `webSocketDebuggerUrl`
- 连上后用 `{id, method, params}` 发命令，按 `id` 匹配响应
- 事件（`Network.responseReceived` 等）进队列，`c.events` 累积

想换成自己的浏览器？设 `DOUYIN_BROWSER` 环境变量即可。

## 四、五个必须知道的坑

### 坑 1 · 骨架页与占位流

页面先渲染骨架，`<video>.currentSrc` 早期是 71 字符占位流或 `blob:`（MSE）。
判定条件（`real_stream()` / `ready()`）：

- URL 必须匹配 `douyinvod` / `video/tos` / `.mp4` / `/media/`
- 正文里「视频数据加载中」必须消失
- 50 秒上限，超时如实报错

### 坑 2 · 画面流与声音流分离

抖音 CDN 给的是**两个独立地址**。`douyin_auto.py` 只会挑到其中一个，
下下来的 MP4 只有 h264 画面、**没有任何音轨**——ffprobe 只列出一条 video 流，
ffmpeg 会报 `Output file does not contain any stream`。

要音频必须单独走 `douyin_audio.py`：
在**页面上下文**里 fetch 作品详情（页面自己的 JS 补签名）→
解析 `aweme_detail.music.play_url.url_list` → 下载 → ffprobe 验「确有音频流」→ ffmpeg 转 mp3。

### 坑 3 · 批量挑流会串

批量复用一个 CDP 会话时，挑流**只能认当前页**：

1. `<video>.src`
2. 本页 `performance` 资源表
3. 本轮导航（`since=mark`）产生的响应

混进历史响应 → **所有视频下载成同一个文件**。
只挑第一个响应 → 可能拿到 0 字节的探测流。
挑流不稳就回退到「逐条调用 `douyin_auto.py`」，实测 10/10 可靠。

### 坑 4 · DOM 里的链接大多不是本人的

视频页 DOM 中 `/video/` 链接**大多数是推荐区的别人的作品**（实测 0/12 命中目标）。
唯一可靠的归属校验是 `detail.author.sec_uid == 目标sec_uid`。

### 坑 5 · 「扒全 N 条」不可达

服务端对未登录/风控会话只暴露**最近 38 条**——把 `count` 从 1 调到 500，全部收敛到 38。
平台页面上的 `aweme_count`（如 133）还包含**非视频作品**与**风控折叠项**。

所以本项目做的是：**尽力遍历 + 如实报告覆盖率**（`coverage.json` 直接对照平台声明总数），
**绝不虚报条数**。想补齐历史，唯一干净路径是**每日增量账本**长期累积。

## 四·五、工程细节：可移植性与性能

### 路径与依赖的三级查找

`scripts/config.py` 统一解析，顺序是 **环境变量 → 系统 PATH → 常见安装位置**：

```
DOUYIN_OUT / DOUYIN_FFMPEG / DOUYIN_FFPROBE / DOUYIN_BROWSER /
DOUYIN_BROWSER_CHANNEL / DOUYIN_BROWSER_COOKIES / DOUYIN_PROFILE
```

解释器永远用 `sys.executable`，分析器用 `os.path.dirname(os.path.abspath(__file__))` 定位，
**不依赖当前工作目录**——所以被 Skill 从任意目录调用都能跑。

### 三个必须处理的工程细节

| 细节 | 坑 | 处理 |
|---|---|---|
| **浏览器 profile 锁** | `auto` 与 `channel` 共用一个 `user-data-dir` 时，第二个浏览器起不来 | 各用独立子目录 `auto` / `channel` / `audio` |
| **系统代理劫持 CDP** | 机器上设了 `http_proxy` 时，`urllib` 请求 `127.0.0.1:9224` 会被代理接管而失败 | 用 `build_opener(ProxyHandler({}))` 单独开一个**不走代理**的 opener |
| **OCR 模型重复加载** | 批量模式每条视频起一个子进程跑 OCR → 模型加载 N 次，每次 2–3 秒 | `douyin_analyze.get_ocr()` 全局缓存引擎；`douyin_channel` 改为**进程内**调用 `analyze_video()` / `write_outputs()`，顺便省掉 N 次进程启动 |

### 依赖预检

每个入口脚本启动前跑 `config.check_deps()`（crawler 另跑 `check_playwright()`），
缺什么直接列出来并给出安装方法，不让用户读到一半的 traceback。

## 五、创作者全量采集的算法
`douyin_crawler.py` 用的是**视频页 BFS**：

1. 主页接口拿一批作品 ID（但只有 38 条，见坑 5）
2. 打开某个视频页 → 该页 DOM 会带出**同一作者更早的作品**
3. 对每个新 ID 打开视频页 → 从 `aweme/detail` 响应里取 `author.sec_uid`
4. `sec_uid` 与目标一致才计入（排除推荐视频）
5. 增量写 JSONL（断点续传），单条失败不中断

工程细节：

- DOM 抓取限定在「**含作者主页链接的祖先容器**」内，以排除推荐视频
- 单条失败不中断整体
- 覆盖率对照平台 `aweme_count`，不虚报
- ≈5 秒/条

## 六、OCR 流水线

```
ffmpeg -i video.mp4 -vf fps=1/N -frames:v M -q:v 5 frame_%04d.jpg
   → RapidOCR（ONNX 运行时，自带轻量模型，不联网）
   → 相邻帧同文字合并成时间段
   → transcript.md + transcript.srt + report.json
```

- 用 JPG 不用 PNG：PNG 单帧 3–4 MB，长视频会攒几百 MB；JPG 每帧约 200 KB
- 相邻帧文字去重合并，避免时间轴被同一句话刷屏
- 置信度 < 0.5 或长度 < 2 的直接丢弃
- 识别不到就写 0 条，**不编造**
